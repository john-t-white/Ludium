Ludium — first-pass mockups

Assumptions baked in: not a review site — play logs capture how a game felt, and that signal drives matches to similar games and to people who felt the same way. No in-app selling, just connecting. BGG import runs async from the Shelf, not during onboarding. Bold/warm dark + amber palette, geometric sans (Sora/Inter). Focused for now on landing, sign-in/onboarding, and My Shelf — Dashboard and Game detail are set aside until we're ready for them.

Open questions
  • BGG's public API has no "bio" field — the verification-code flow assumes we'd scrape the profile page, which is fragile and likely against API terms. Need a field the API actually returns (e.g. stateorprovince) or a different verification approach.
  • Verification code: HMAC(Google ID + server secret) only for the pre-account window (survives the user leaving mid-setup); once "Finish setup" creates the account, store the code permanently on the account record — simpler than key-rotation for anything post-signup.
  • Should the location field (for player matching) be required at signup, or can users add it later from Settings?
  • Verify BGG connection is required before "Finish setup" only if a BGG username was entered — skipping the username field skips verification too.
  • Discovery/recommendations and the "games to get rid of" flow are still out of scope for this pass — need a decision on when to design those.
  • No decision yet on trading/selling handoff — confirmed Ludium won't handle transactions, but what does "connecting" two matched users actually look like (in-app chat? shared contact info?).
